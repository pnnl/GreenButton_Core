# Headless OAuth-Style Flow (Frontends-Only Navigation)
This document provides a usage overview of the 
PETSAFE (Privacy Enhancing Testbed for Secure meter Aggregation and Energy benchmarking) project

This document describes the implemented browserless authorization code flow between:

- PETSAFE_CUSTODIAN_FE: The "Utility/DataCustodian Frontend", located at http://localhost:8080
- PETSAFE_THIRD_PARTY_FE: The "Third Party Frontend"
located at http://localhost:9090
- ESPI DataCustodian Backend (Spring) at /DataCustodian
- ESPI ThirdParty Backend (Spring) at /ThirdParty

## Core Principles
1. Browser only navigates between the two React frontends (`/confirmation` on PETSAFE_CUSTODIAN_FE, callback on PETSAFE_THIRD_PARTY_FE).
2. All sensitive OAuth form submissions (`/oauth/authorize`, `/oauth/token`) occur server-to-server using established user sessions (JSESSIONID), never directly from the browser.
3. State parameter is generated by the PETSAFE_THIRD_PARTY_FE and validated during token exchange; single-use and cleared after success.
4. Privacy level is represented as a `privacy:<level>` scope (e.g., `privacy:full`). Additional scopes are individually user-approved.

## Sequence
1. PETSAFE_THIRD_PARTY_FE user clicks Connect → POST /ThirdParty/api/auth/initiate
2. Backend returns JSON: `{ client_id, redirect_uri, scope, state }`
3. Browser redirects to PETSAFE_CUSTODIAN_FE: `http://localhost:8080/confirmation?...`
4. PETSAFE_CUSTODIAN_FE loads scopes/levels via GET /DataCustodian/api/auth/scopes
5. User approves → PETSAFE_CUSTODIAN_FE POST /DataCustodian/api/auth/consent (JSON)
6. DataCustodian backend performs internal POST to /DataCustodian/oauth/authorize, intercepts 302, returns `{ code, state, redirect_uri }` JSON
7. PETSAFE_CUSTODIAN_FE frontend redirects browser back to PETSAFE_THIRD_PARTY_FE callback with `?code&state`
8. PETSAFE_THIRD_PARTY_FE callback POST /ThirdParty/api/auth/exchange (JSON) → backend POST /DataCustodian/oauth/token
9. ThirdParty backend validates state, persists Authorization with tokens, returns token JSON to frontend (PETSAFE_THIRD_PARTY_FE).

## New / Updated Endpoints
### OpenESPI ThirdParty Backend
- POST /ThirdParty/api/auth/initiate → generates state, returns initial params
- POST /ThirdParty/api/auth/exchange → validates state, exchanges code, persists Authorization

### OpenESPI DataCustodian Backend
- POST /DataCustodian/api/auth/consent → headless authorize (captures code)
- GET  /DataCustodian/api/auth/scopes → lists available scopes & privacy levels

## Frontend Utilities (PETSAFE_CUSTODIAN_FE, PETSAFE_THIRD_PARTY_FE)
Both frontends have `src/utils/http.ts` providing a fetch wrapper that redirects to `/login` on 401.

## Dynamic Consent
Stars `Confirmation.tsx` fetches scopes/levels and renders approval radio groups. Approved scopes are sent as `scopes: { "scope.<Name>": "true" }` plus `privacy_level`.

## State Handling
- Generated in `/api/auth/initiate` using 128-bit SecureRandom, Base64URL encoded.
- Stored in HttpSession key `OAUTH_STATE`.
- Validated & cleared in `/api/auth/exchange`.

## Persistence
`/api/auth/exchange` stores minimal Authorization (access token, refresh token, expires, state, code, scope) via `AuthorizationService.persist`.

## Cleanup / Legacy
`AuthorizationApproval.tsx` (PETSAFE_CUSTODIAN_FE) deprecated; retained short-term with comment. Legacy JSP/UI flows are bypassed.

## Error Flows
- Deny on Stars → redirect to PETSAFE_CUSTODIAN_FE with `?error=access_denied&state=...`
- Missing / mismatched state → 401 from `/api/auth/exchange`.
- Session expiration before consent or exchange → 401 triggers frontend login redirect.

## Security Notes
- State is single-use and removed after exchange.
- All server-to-server calls reuse authenticated session via cookies.
- Privacy levels are enforced downstream during data export based on `privacy:<level>` scope.
